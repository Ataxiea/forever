# SIML, compressed (siml.llm.txt)

SIML is the text format of WoWSims Forever's rotations (APLs), gear sets and whole sim setups. Each file reads as a
proto (proto/apl.proto, proto/api.proto) and back, 1:1. This file is written by `wowsimcli siml llm`; edit
sim/siml/llm_head.txt for the part above "Actions". The full language is sim/siml/SPEC.md, which wins on any doubt.

## Where things are

- sim/siml/SPEC.md           the language; §6 rotations, §7 names, §8 what the protos derive, §13 diagnostics
- sim/siml/names.json        every name a file may write, per class and namespace (generated: make siml-names)
- sim/siml/forms.json        sections, units, short forms; everything else comes from the protos
- sim/siml/testdata/         the corpus: parse/ (text and the JSON it reads as), errors/ (with .diag), format/, splice/
- ui/specs/<class>/<spec>/   defaults.siml, apls/*.apl.siml, gear_sets/*.gear.siml, builds/*.siml (the presets)
- cmd/wowsimcli/cmd/siml*.go the CLI; sim/siml/lsp the language server; tools/vscode-apl the VS Code extension

## CLI (build it with the database: go build --tags=with_db -o bin/wowsimcli ./cmd/wowsimcli)

- siml parse [-json] f            does it load; -json prints the proto it reads as
- siml fmt -check|-w <paths>      canonical form; under ui/specs also warnings, raw refs and stale names
- siml print -kind apl|gear|siml [-spec hunter] x.json    JSON as SIML
- siml verify x.json x.siml       does x.siml read back as x.json
- siml sim < request.json         sims an .apl.siml text (the editor's sim)
- siml lsp                        the language server on stdin/stdout (LSP 3.17, JSON-RPC with Content-Length)
- make siml                       regenerates names.json and this file, then runs fmt -check ui/specs

## Language server

Start `bin/wowsimcli siml lsp` (built with --tags=with_db) with the repository root as its working folder, and send
`.siml` documents (languageId siml). It answers completion, hover, definition, references, rename, document
symbols, folding, semantic tokens, formatting, code actions (quick fixes) and document links, and publishes
diagnostics. Names complete from sim/siml/names.json, items from the database. VS Code: tools/vscode-apl (built into
.vscode/extensions/wowsims-apl) builds and starts the server itself.

## Files

- `x.apl.siml` a rotation; `x.gear.siml` a gear set (no spec line needed); `x.siml` a full setup with sections.
- First lines: `siml 1`, then `spec <Player spec oneof field>` (hunter, dps_warrior, retribution_paladin, …), then in
  an x.siml optionally `talents "…"` and `use "path" [with $var = value, …]` (takes another file's sections in).
- `// comment` anywhere (never reaches the proto); `/// note` above a priority or group row is its notes;
  `# ` before a row hides it (kept with "hide": true). Indent with 2 spaces; a long row continues on deeper lines.
- Raw JSON in backticks stands for anything with no SIML form: `` cast `{"spellId":31016}` ``.

## Setup sections (x.siml)

settings: consumables: buffs: party_buffs: raid_buffs: debuffs: encounter: sim: gear: item_swap: apl: simple:
cooldowns: prepull: priority: group "<name>":
Entries are `field value` lines or comma lists of flags (`raid_buffs:` `gift_of_the_wild, battle_shout`); `sim:
iterations 25000` fits one line. Gear rows: `<slot> <item> [<suffix>] [+ <enchant>]`, slots head neck shoulder back
chest wrist hands waist legs feet finger1 finger2 trinket1 trinket2 main_hand off_hand ranged.

## Rotations

```
siml 1
spec hunter

var ${Use Multi-Shot} = true          // a sim variable: a value read while the fight runs; $use_multi_shot
def fits(x) = spell(x).cast_time < 2s // a def: text substituted where it is called, parameters replaced
def filler = arcane_shot              // a def that is a name stands for it where a name goes

prepull:
  -2s cast aspect_of_the_hawk         // a prepull row starts with its time

priority:
  cast hunters_mark if not target.aura(hunters_mark).is_active
  cast multi_shot if $use_multi_shot and fits(multi_shot)
  when current_time > 5s:             // joins its condition to every row under it
    cast filler if spell(filler).is_ready
  group "Weave" if self.unit_distance > 5
  cast rapid_fire if current_mana_percent >= 50%

group "Weave":
  move 5
  wait 400ms
```

Steps: `cast x [on unit]`, `channel x [on unit] [until value] [recast]`, `wait v`, `wait until v`, `move v`,
`move for v`, `group "N" [with %p = v]`, `schedule "0s, 60s" <step>`, `sequence "N" [a, b]`, `none`, any action kind
below, bare (`autocast_other_cooldowns`) or with arguments (`multidot(rend, max_dots=3)`). `if <value>` conditions a
row.
Values: `1.5s 400ms 1m30s 30% 7 true false "text" none`, `$var` / `${Exact Name}`, `%placeholder` (a group's),
`and or not`, `== != < <= > >=`, `+ - * /`, `max(a, b)`, `min(a, b)`, `[unit.]head(x).property[(arg=v)]`,
`[unit.]kind`, `kind(…)`, a def call. Precedence loosest first: or, and, not, comparisons, + -, * /.
Arguments: positional first, then `field=value`; a bool field written bare sets it, and the printer writes
`is_active(include_reaction_time=true)`.
Units: self target previous_target next_target all_targets all_players targetN playerN petN (N from 1) none.

## Names

A name is the game name in snake_case, read in a namespace by position: spell (cast, spell(), dot()), aura (aura()
on self/player/pet), target_aura (target.aura()), target_spell (boss_spell()), pet_aura, item, enchant, suffix.
Spell-like names are the file's class's, else shared (gear, consumables, encounters). Items in a spell position are
`item.<name>` (`cast item.major_mana_potion`); `other.<name>` is an OtherAction (`other.offensive_potion`). Ranks
and duplicates carry suffixes: `frostbolt_rank10`, `heroic_strike_tag1`, `fireball_18082`. A name the table lacks is
`unknown-name` with a did-you-mean; `make siml-names` adds new registered spells.
`$var` where a name goes (`cast $filler`, `aura($curse)`) is the spell the variable holds, once ActionID has a string
member to name a variable in; until then it is `spell-variable`.
